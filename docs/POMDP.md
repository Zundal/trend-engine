# 부분관측 마르코프 결정과정(POMDP) — 확산 단계의 믿음과 결정

`diffusion.py` 는 매일 17주 창을 보고 단계를 **하나 찍는다**(확산 대기 / 확산 중 / …). 어제 무엇이었는지는
보지 않고, 임계값(붐 1.6배, 활성 50%, 시차 2주) 경계에 걸린 키워드는 날마다 판정이 뒤집힌다. 알림은
"단계가 바뀔 때" 울리므로 뒤집힐 때마다 다시 울린다. 추적 목록은 10·20대 순위에서 빠지면 곧바로
빠지는데, 그 순간이 바로 윗세대 파도가 도착하는 때다.

이 둘은 같은 문제다: **진짜 상태(유행의 국면)는 보이지 않고, 매일의 판정은 그 상태를 잡음 섞어 관측한
것이며, 검색 데이터 요청은 한정된 예산 안에서 골라 써야 하는 행동이다.** 그래서 POMDP 로 쓴다.

## 정의 — `pomdp.py`

| 요소 | 이 엔진에서 |
|---|---|
| 은닉 상태 S | 국면 5개: `휴면`(꾸준한 관심·유행 아님) → `청년 상승`(10·20대만 붐) → `확산`(윗세대로 번지는 중) → `퇴조`(고점 지남) → `휴면`. 뉴스 충격은 `휴면 → 전 연령 → 퇴조` 로 따로 간다. |
| 관측 O | 그날의 규칙 판정 6개(확산 대기·확산 중·윗세대 상승·전 연령 동시·지나감·상시 관심). 관측 행렬 P(판정 \| 국면)은 혼동 행렬이다 — 예: `청년 상승` 국면이 "상시 관심"으로 읽힐 확률 15%. |
| 전이 T | 주 단위 마르코프 사슬. 대각선이 무겁고(국면은 몇 주 지속), 앞으로만 가는 질량이 대부분. |
| 믿음 b | 키워드마다 국면 5개 위의 확률. 매 실행 `b' ∝ O(o\|s)^w·Σ T(s\|s')b(s')`, w = 날수/7 (최대 1). 실행 사이의 날수만큼 T 를 분수 거듭제곱하고, **관측 우도도 같은 비율로 누그러뜨린다** — 하루 뒤의 판정은 17주 창을 하루 밀어 다시 읽은 것이라 새 증거의 1/7 뿐이다(안 그러면 하루 관측 7번이 일주일 관측 7번으로 세어져 백테스트보다 훨씬 빨리 확신에 이른다). 저장소에 보관(`belief:v1`) → **실행 간 기억**. |
| 행동 A | ① 알림: 믿음이 `청년 상승`/`확산` 에 ≥ 50% 일 때만 단계 알림을 통과시킨다(원판정만으로 울리지 않음). ② 측정: 다음 실행에 어느 키워드에 요청을 쓸지 — 아래. |
| 보상 R | 평가에만 쓴다(정책 최적화 안 함): 윗세대 상승 8주 전 안에 낸 알림 +1, 안 따라온 알림 −1, 요청 1건 −c. |

## 진화 — 매 실행 다시 배운다
T 와 O 는 고정 상수가 아니다. 두 종류의 **키워드별 주간 판정 수열**에 Baum-Welch(EM)를 돌려 다시 추정한다:
1. 워크포워드 백테스트가 만드는 수열(이미 매 실행 계산됨, 추가 요청 없음) — 늘 같은 42주 창이라 이것만으로는 축적이 없다.
2. **아카이브의 일별 단계 기록**(`archive/<날짜>/diffusion.json`, data 브랜치) — 주마다 마지막 날의 판정 하나로 표본화하고
   빠진 주에서 수열을 끊는다(`pomdp.weekly_sequences`, `archive.diffusion_sequences`). 이것이 날마다 자란다.
사전 분포(디리클레 의사 계수 `PRIOR_WEIGHT`)가 있어 표본이 적을 때는 손으로 넣은 초기값에 머물고, 데이터가 쌓일수록
데이터 쪽으로 옮겨간다. 학습된 행렬은 `pomdp-model:v1` 에 저장되고(믿음 갱신이 이 모델을 쓴다) 확산 payload 의
`model` 로 함께 나간다.

국면 이름은 사전 관측 행렬이 정한다(EM 은 라벨을 바꿀 수 있으므로, 각 국면의 사전 최빈 판정이 그대로
최빈으로 남는지 검사해 뒤집혔으면 사전값으로 되돌린다 — `fit()` 의 `label_locked`).

## 측정 배분 — `pomdp.plan`
요청 예산 = 추적 키워드 수. 우선순위:
1. `watchlist.txt` 고정.
2. **붙잡기**: 믿음 질량 P(청년 상승)+P(확산) ≥ `HOLD`(0.35) 이면 10·20대 순위에서 빠져도 계속 잰다.
   결정이 걸려 있는 키워드는 정보의 가치가 가장 크다. 단 예산의 절반(`HOLD_SHARE`)까지만 — 새 후보 자리는 남긴다.
3. 후보(기존 휴리스틱 순서). 단 **가라앉은 키워드**(P(휴면) ≥ 0.9 가 3회 연속)는 7일에 한 번만 잰다 —
   게임·대형 브랜드가 매일 예산을 먹지 않게.

## 검증 — 원판정 옆에 나란히
같은 워크포워드에서 믿음도 매주 앞으로만 갱신해 채점한다.
- `belief_accuracy`: "믿음이 청년 상승" 일 때 8주 내 윗세대 상승 정밀도·lift — `accuracy`(원판정)와 같은 표.
- `flips`: 키워드당 주간 판정이 바뀐 횟수, 원판정 vs 믿음 국면. **알림이 얼마나 덜 흔들리는가**가 이 모듈이
  약속하는 개선이고, 이 숫자가 그것을 잰다.
- `alerts`: 같은 수열 위에서 두 알림 정책을 흉내 낸다 — 원판정(알림 단계에 들어설 때마다) vs 게이트(믿음이 동의할 때만,
  마지막 통과 단계 기억). 40대+가 아직 조용할 때 낸 알림만 세고, 8주 안에 따라오면 적중. 게이트가 헛알림을 줄이는지가 여기 나온다.
- `detection`(과거 사례): 40대+가 실제로 오른 첫 주부터 판정이 확산 중/윗세대 상승을 말하기까지, 그리고 믿음이 확산 ≥ 50% 에
  이르기까지 몇 주 걸렸나. **평활의 대가**를 주 단위로 잰다(사전 모델 기준 — 사례는 30일 캐시라 그날의 학습 모델과 무관).
- 예측력이 더 좋다고 주장하지 않는다. 필터는 같은 관측을 시간 축으로 평활할 뿐, 새 정보를 만들지 않는다.

## 안 하는 것
- 가치 반복으로 정책을 푸는 것: 국면 5개짜리 감시 문제의 최적 정책은 믿음 임계 정책이라 임계값만 있으면
  된다(Lovejoy 1987). 임계값은 데이터로 맞추지 않고 0.5 로 둔다 — 같은 데이터로 고르고 채점하는 과적합(ENGINE.md 4b)을 피한다.
- 관측을 늘리는 것: 관측은 여전히 규칙 판정 하나다. 연령별 수준·시차를 직접 관측으로 넣으면 관측 행렬이
  커지고 표본(키워드 50개 × 주 40개)으로는 못 배운다.
