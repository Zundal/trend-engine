# Segments: 연령·성별 관심도

## 무엇을 답하나
"오늘 뜨는 키워드 중 **20대(또는 여성, 50대…)가 다른 사람들보다 특히 많이** 찾는 건 뭔가?"

## 방법 (anchor normalisation)
네이버 DataLab 은 요청마다 최댓값을 100 으로 맞추고, 한 요청에 5개 그룹만 받는다. 그래서:

1. 기준어(anchor, 기본 `날씨`) + 키워드 4개씩 배치로 요청.
2. 세그먼트 s 에서 `rel_s(k) = Σ ratio(k) / Σ ratio(anchor)` — 기준어 대비 검색량.
3. `share_s(k) = rel_s(k) / Σ_k rel_s(k)` — 오늘 트렌드 묶음 안에서의 비중.
4. `affinity_s(k) = share_s(k) / share_전체(k) × 100`.

**100 = 평균, 200 = 해당 그룹에서 비중이 2배, 50 = 절반.**

키가 없으면 datalab.naver.com 웹 폼으로 같은 데이터를 받는다 (docs/SOURCES.md "키 없는 모드"). 2.5초 간격이라 지역당 약 1.5분.

호출 수 = ⌈키워드/4⌉ × (세그먼트 수 + 1). 기본 16키워드 × 9 = 36회/지역. 정적 배포는 지역별 3시간마다만 재계산(export.SEGMENT_REFRESH) → KR·KR-11 기준 월 약 1.7만 회. 응답은 6시간 캐시(같은 키워드 묶음 재사용).

## 10·20대 포커스 (youth.py)
- 그룹: 10대, 20대, 10대 여성·남성, 20대 여성·남성. 비교 기준: **30대 이상** (연령 코드 5–11 한 묶음).
- `vs_older_g(k) = affinity_g(k) / affinity_30대이상(k)` — "30대 이상보다 몇 배 더 찾나".
- 오늘 이슈만 재면 아이돌·게임·상품처럼 10·20대 고유 관심이 빠지므로 후보를 넓힌다:
  오늘 이슈(최대 15) + 인기 영상 태그(최대 20) + 10·20대 쇼핑 고유 키워드(최대 15) → 최대 40개.
- 선정 기준: affinity ≥ 120 이고 vs_older ≥ 1.5. 호출 수 ≈ ⌈40/4⌉ × 8 = 80 (3시간 캐시).

## 기본 세그먼트
10대(13–18) · 20대(19–29) · 30대 · 40대 · 50대 · 60대+ · 남성 · 여성.
조합: `"20대 여성"`, `"20대+30대 남성"` 등 (`parse_segment`).

## 해석 주의 (중요)
- **검색자 수 비율이 아니다.** DataLab 은 절대량을 주지 않는다. "20대의 60%가 검색" 같은 표현 금지.
- 기준어 자체의 세그먼트별 편차가 섞인다 (예: 날씨는 고연령층이 더 검색). affinity 는 **같은 묶음 내 상대 비교**로만 쓸 것.
- 문장형 이슈(`○○ 대법관 임명 재가`)는 검색량이 거의 0 → 표에서 빠진다. 가능하면 Nate 의 짧은 검색어 필드(`query`)를 사용한다.
- DataLab 은 약 1일 지연. 기간 기본 최근 7일.
- 10대(13–18)는 표본이 작아 변동이 크다.
- 오프라인 모드 결과는 **합성**(`synthetic: true`)이며 실제 분포가 아니다.

## 서울 핫스팟 연령 분포와의 차이
`seoul.py` 는 **검색**이 아니라 **실제 체류 인구**(통신 데이터 기반)의 연령 비율이다.
`dominant_group` = 다른 핫스팟 평균 대비 가장 많이 초과한 연령대("지금 성수는 20대가 평소보다 많다").
